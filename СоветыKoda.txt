Почему обычный diff делает мясорубку
Ваш файл — это XML правил КД2, где внутри тегов лежат многострочные куски кода 1С. Обычный diff (git, Beyond Compare, kdiff3) сравнивает файл по номерам строк: строка 500 одного файла против строки 500 другого. Как только перед вашим куском текста в develop добавили 20 строк, все последующие строки «съезжают», и diff начинает сравнивать конец одного правила с началом другого — две разные сущности. Это и есть мясорубка.

Что сделал: 
kd2_merge.py
Скрипт не сравнивает строки вообще. Он разбирает оба файла на сущности (Группа / Правило / Свойство / Значение / Алгоритм) и сопоставляет их между файлами по идентичности (Наименование, Источник→Приемник), а не по позиции. Diff строится только внутри одной сущности — сравнить два разных правила технически невозможно.

По ходу отладки нашёл и обезвредил две причины ложных конфликтов:

<Код> у Свойств/Значений — авто-нумерация КД2, которая пересоздаётся при каждом экспорте (у develop 144, у вас 6 — это одно и то же свойство). Такие поля (Код, Порядок) теперь не считаются правкой и всегда берутся из develop.
Сопоставление по «похожести» только при очень высоком пороге (0.85) — переименованная сущность найдётся, а разные сущности не склеятся.

Как пользоваться
Запуск
# только отчёт, ничего не меняется
python kd2_merge.py analyze --develop "(develop).xml" --mine "(изменения).xml"

# слить (результат = develop + ваши правки)
python kd2_merge.py merge --develop "(develop).xml" --mine "(изменения).xml" --out "(merged).xml"
Совет на будущее: возьмите base из git
Сейчас режим 2-way: без общего предка спор «кто это менял» решается эвристикой. Если у вас файл лежит в git — дайте скрипту третью версию (ту, от которой вы ответвились):

Запуск
git merge-base origin/develop my-branch            # хеш общего предка
git show <хеш>:путь/к/файлу.xml > base.xml         # выгрузить его версию
python kd2_merge.py merge --develop "(develop).xml" --mine "(изменения).xml" --ancestor base.xml --out "(merged).xml
С --ancestor слияние полностью честное 3-way: блок, который меняли только вы, возьмётся из вашего файла автоматически (и тот единственный спор, скорее всего, разрешится сам, если правку develop сделана раньше вашего ветвления).
